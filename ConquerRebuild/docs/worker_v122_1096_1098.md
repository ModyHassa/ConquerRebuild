# worker_v122 — action types 1096 and 1098

Bodies resolved from the router tables (not copied): **1096 = 0x140137fa5**,
**1098 = 0x140138322**.

## 1096
- `sscanf(param, "%d %d %d %d %d %d")` — **all six** tokens must parse; the five
  after the first must be `>= 0`, otherwise the shared fail epilogue is taken
  (`id_nextfail`).
- The action's `data` column is then used as an **id**, and the body asks a
  provider through `vt+0xd8`.
- If the provider does not know the id, the body calls `vt+0x8` with **nine**
  arguments; that call's **return value is the action's result** (true -> `id_next`,
  false -> `id_nextfail`).

## 1098
- `sscanf(param, "%d %d %d ... %d")` — **15 ints**, of which 1..15 may be present
  (the count of parsed tokens is the mode selector).
- mode 0: succeeds if **any** listed entry exists (OR reduction).
- mode 1: takes the **first existing** entry and records it.

Both bodies are small; the remaining work before a port is naming the provider
object behind `vt+0xd8` / `vt+0x8` (same helper family the other 1xxx types use).
Status: **decoded, not ported**.

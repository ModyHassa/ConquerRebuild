# Worker v125 — action 544 (super-flag push) and 2009 (map-spawn) portability

## 544 — corrections, and why it stays BLOCKED
* The id pushed to the client is **not** the handler's 10th argument: it is **`param_6`**, the
  context byte at `+0x18` of the fifth `ProcessAction` parameter (`mov WORD [rsp+0x28],bx` where
  `ebx` is that byte). The v124 note saying "10th argument" is superseded.
* Record layout sent in packet 2110 is 0x30 bytes: **four numeric values taken from CItemData
  columns** plus a **0x20-byte string**.
* Packet: type **2110 (0x83E)**, size `0x4C + 10*0x30`, recipient = the acting user only
  (`user+0x10` vt `+0x350`).
* **BLOCKED**: `cq_super_flag` has **0 rows** in the shipped DB and the rebuild has no
  SuperFlagMgr loader, so nothing can populate the 10 records the packet carries. Porting it now
  would only ever emit an empty 2110.

## 2009 — spawn entry refinements
* Exit paths write **6 or 10** into the element (not always 10 as v124 said).
* Accepted `type` window is **11185761 .. 11285759** inclusive.
* Still needs the full `0x14038E270` body to define every field it writes and the exact payload of
  the 10010 action-135 notice.
* Status: **UNKNOWN / not ported**.

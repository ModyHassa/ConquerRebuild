- token1 vocabulary (all literals read in v143): **count** (0x14070e334), **money** (0x14070977c),
  **level** (0x1406ef6c8), **mate** (0x14070f070), **friend** (0x14070e32c), **istogether** (0x14070e320).
- `count` branch: `singleton->vt[0x50](id,0)` compared with the %I64d value: `<` → pass when count < v,

- else branch: enumerates a container (`vt[0x60]`), skips the entry whose `vt[8]() == user id`, then per
  entry: money → `vt[0x180](v,1)` / `vt[0x60]()` compares; level → `vt[0x70]()` compares;
  mate → `0x140164460(obj,user)` + `vt[0x220]()`; friend → `0x1401183a0` `vt[0x170]` + `vt[0x220]()`;
  istogether → `vt[0x220]()`; no match → 0.
- Rows: 5031061/63/64/65 = `count == 2/3/4/5` (a ladder), 7607510 `count == 2`, 7607516 `mate`.
**BLOCKED**: the meaning of instance slot 30's `vt[0x50]`/`vt[0x60]`/`vt[0x180]`/`vt[0x220]` and of
`0x140118800` / `0x140164460`. 5 of 6 rows would work with the `count` branch alone, but a partial port

# Worker v124 — action type 3701 (task quota family)

Binary: `conquer_source/Source/MsgServer.exe`
Image base `0x140000000`. Sections confirmed by PE header parse:
`.text` VA `0x140001000` (file off `0x400`), `.rdata` VA `0x1406d8000` (file off `0x6d6600`).

Decoded from live disassembly (`objdump -d -M intel`) cross-checked against
`decompiled/MsgServer.c`. Line cites are `MsgServer.c:LNNNNN`; address cites are VAs.

---

## 0. Verdict up front

3701 is **not** a DB quota action. The handler executes **zero SQL** and touches **no `cq_*`
table**. It is a pure *user-state / visual-flags* action: it stamps two string fields and two
integer fields on the acting user (`+0x130..0x168`), pushes one `0x56` manager notification,
and broadcasts **one** `CMsgAction` (id `10010`) carrying action code **`0xA4`** to the map.
This contradicts the "task quota family" label in the task brief — see §8.

## 1. Dispatcher and the family guard

`MsgServer.c:223710-223717`:

```c
if (iVar8 - 0xe75U < 0x62) {                       /* 3701 .. 3798 */
  ...
  FUN_14011dcb0(param_1, puVar10, &local_c38, *(undefined8 *)(param_1 + 8));
  DAT_140975d64 = DAT_140975d64 + -1;
  return '\x01';
}
```

* `0xE75` = **3701**. `0x62` = 98, so the guard covers 3701..3798 inclusive.
* Enclosing dispatcher is `FUN_1400ffdf0` (starts `MsgServer.c:189519`).
* `DAT_140975d64` is the action-recursion depth counter — incremented at `MsgServer.c:223543-223544`
  (`if (DAT_140975d64 < 0xb)` = overflow guard at depth 11), decremented here at `:223715`.

### CRITICAL: the handler's return value is discarded by the dispatcher

Address `0x14011dcb0` is called at `0x14014690a`-region (`MsgServer.c:223714`) as a plain
`call` with **no** assignment; the dispatcher then executes an unconditional
`return '\x01'`. Every *other* family in the ladder assigns `cVar1 = FUN_...(...)` and honours
it (`MsgServer.c:223728+`).

Consequence: **for 3701..3798 the id_next/id_nextfail choice is made unconditionally, and it is
always id_next.** The `al` value that `FUN_14011dcb0` computes is dead at the call site.
(Verified: `0x14011dcb0` epilogue writes `al` at `0x14011dffc` = `mov al,0x1` and
`0x14011e035` = `xor al,al`; both are discarded.)

## 5. The sscanf format

Buffer setup `0x14011ddd5-0x14011ddf2`:

```
mov  byte [rsp+0x4e0],0        ; local_148 = '\0'      (1-byte leader)
mov  r8d,0xff
lea  rcx,[rsp+0x4e1]           ; local_147[255]
call 0x140512630               ; memset(local_147, 0, 0xff)   -> 255-byte zeroed array
mov  dword [rsp+0x60],0        ; local_5c8 = 0    <- int #1 out
mov  dword [rsp+0x68],0        ; local_5c0[0] = 0 <- int #2 out
```

Call `0x14011de47-0x14011de68`:

```
mov  [rsp+0x20], &local_5c0[0]   ; 4th vararg (stack, slot at rsp+0x20)
lea  r9,[rsp+0x4e0]              ; 3rd vararg = local_148 (char[256] at 0x4e0..0x5df)
lea  r8,[rsp+0x60]               ; 2nd vararg = &local_5c8
lea  rdx,[0x14070c758]           ; format
mov  rcx,rbx                     ; the parameter string
call [0x1406d8ab0]               ; sscanf
cmp  eax,0x3
jne  0x14011e000                 ; must consume exactly 3
```

**Resolved format string at `0x14070C758` = `"%d %s %d"`.**

Therefore the `cq_action.P` parameter text is:

```
<int>  <string>  <int>
```
* `%d` → `local_5c8` (`[rsp+0x60]`) — **int A**
* `%s` → `local_148`/`local_147`, a `char[256]` at `rsp+0x4e0` — **string S** (no width
  specifier ⇒ unbounded; caller-side 255 zeroed bytes)
* `%d` → `local_5c0[0]` (`[rsp+0x68]`) — **int B**

Guard `0x14011de77-0x14011de83`: `cmp dword [rsp+0x60],r14d` / `jg 0x14011de85`.
`r14d` was zeroed at `0x14011ddf2`. So **`if (int A <= 0) return 0;`** — int A must be **>= 1**.

Failure path `0x14011e000-0x14011e035` (sscanf != 3):
* `call [*param_2 vtable +0x20]` with `"id"` (`0x14094da3c`), then `[+0x40]` → the row id
* logs `0x14070c010` = `"table:cq_action/cq_newaction, ACTION %u: 错误的参数数量 at %s, %d"`
  (GBK `´íÎóµÄ²ÎÊýÊýÁ¿` = 错误的参数数量 = "wrong parameter count"), with
  `r9 = 0x37C9` = **14281** as the line argument and `r8 = 0x14070bbd0` the file path.
* **returns 0.**

`0x14070bbd0` = `"f:\version\cqserver-78.0.11-1204\msgserver\mapgroupkernel\gameaction.cpp"` —
confirms the build and the original source unit for all log calls in this function.

## 7. Branch outcomes — id_next vs id_nextfail

| Path | Address | Handler `al` | Dispatcher result |
|---|---|---|---|
| `param_2 == NULL` | `0x14011dd05` | 0 | **id_next** (unconditional `return '\x01'`) |
| `param_4 == NULL` | `0x14011dd64` | 0 | **id_next** |
| action_type != `0xE75` (i.e. 3702..3798) | `0x14011ddce` | 0 | **id_next** |
| dead flag bit0 set → `STR_DIE` | `0x14011de40` | 0 | **id_next** |
| `sscanf != 3` | `0x14011e035` | 0 | **id_next** |
| `int A <= 0` | `0x14011de7e` | 0 | **id_next** |
| success | `0x14011dffc` | 1 | **id_next** |

**The outcome is id_next on every path.** The handler's boolean is dead code at the call site
(§1). A rebuild must NOT wire 3701 to id_nextfail on any error path. The only real "abort"
signal is the recursion-depth guard `DAT_140975d64 >= 0xb` at `MsgServer.c:223542`, which is
handled *before* the family dispatch and is common to all types.

Failure side effects that still happen on abort paths:
* `param_4 == NULL` path calls the `"id"` getter (`0x14094da3c`) and `vtable+0x40`.
* `sscanf != 3` path also calls the `"id"` getter and `vtable+0x40`.
* The type-mismatch path calls cell-3 getter `+0x48` and the `"id"` getter.

## 8. Quota / counter semantics — what is proven, what is not

**Proven:** there is no quota, no counter, and no persistence. No SQL, no DB write, no
`++`/`--` on any user counter in the body. `user+0x134`, `+0x138`, `+0x13C` are **zeroed**
(never incremented) and `user+0x130` is a `char` set to `0`.

`user+0x130..0x168` is a **user-state descriptor block** written only by `FUN_140164e30`, of the
shape `{char active; int f1(0x134); int f2(0x138); int f3(0x13C); std::string s1(0x140);
std::string s2(0x168)}`. The `param_2 != 0` branch of `FUN_140164e30` sets
`active=1, f1=param_3, f2=param_4, f3=param_5, s1=param_6, s2=param_7` — a classic
"set/clear a user status line" record. `FUN_140164e30` is called with `param_2 = 0` here, i.e.
3701 **clears** the block.

Plausible (but **UNKNOWN**, not proven): the block backs the client's on-screen
status/notice slot, and `0xA4` is the "refresh status" opcode broadcast to nearby players so
they re-render the actor. Evidence for idleness of the block outside the ctor: no other call
site in `MsgServer.c` writes `user+0x134/0x138/0x13C`.

⇒ **UNKNOWN:** the semantic name of the `0x130` block, the meaning of `STR_DIE` delivery via
`+0x358`, `0x56`, `0xA4`, and whether int A / int B are `seconds` and `count` (the
"quota" reading) — no code in this handler uses them as a quota; A is only a `>0` gate and a
packet field, B is only a packet field.

## 9. Sibling types in the same switch (3702..3798)

The statement `if (iVar8 - 0xe75U < 0x62)` (`MsgServer.c:223710`) sends **all of**
3701..3798 to `FUN_14011dcb0`. Inside, the type gate (§3) compares against `0xE75` only, so:

| Type | Hex | Note |
|---|---|---|
| 3701 | `0xE75` | the only implemented case (§2-§6) |
| 3702 | `0xE76` | falls to `0x14011dd89`: logs "unsupported ACTION type" → return 0 → **id_next**, no effect |
| 3703 | `0xE77` | same, no effect |
| 3704 | `0xE78` | same, no effect |
| 3705 | `0xE79` | same, no effect |
| 3706 | `0xE7A` | same, no effect |
| 3707 | `0xE7B` | same, no effect |
| 3708 | `0xE7C` | same, no effect |
| 3709 | `0xE7D` | same, no effect |
| 3710 | `0xE7E` | same, no effect |
| 3711..3798 | `0xE7F..0xED6` | same, no effect |

There is **no** `switch` with per-case bodies in this function — the decompiled
`switch`-like look is the dispatcher ladder in `FUN_1400ffdf0`, not this handler. The
`0x62` span is therefore **98 type slots wired to one handler of which exactly one does
anything**; the other 97 are logged no-ops. (This is why the "quota family" label is
misleading: there is no family.)

For contrast, the immediately following sibling *family* is `0xED9` = **3801..3898**, handled by
`FUN_14011bfa0` (`MsgServer.c:223717-223721` = `ProcessActionFactionMatch`), which itself only
implements `0xED9..0xEDD` (3801-3805) and `0xEDE` (3806).

## 10. Rebuild requirements (what a port must reproduce)

1. Gate on action type == `3701` and on the user NOT having status-byte bit 0 set.
2. `sscanf(P, "%d %s %d")` must yield 3; else log "wrong parameter count" and continue to
   id_next with no side effects.
3. `if (int A < 1)` → no side effects, id_next.
4. Clear the user status block (`+0x130`..`+0x168`): active=0, f1=f2=f3=0, s1="".
5. Send manager notification code `0x56` for the user's sub-object id.
6. Broadcast one `10010` `CMsgAction` on the actor's map to everyone including self:
   action `0xA4`, subject = actor uid; u16 fields `+0x14 = 0xA4`, `+0x16 = 1`, `+0x18 = 0`,
   `+0x1A = 0`; u32 fields `+0x08 = int B`, `+0x20 = int A`, `+0x1C = 0`; packed string empty;
   payload size = packed-string size + `0x25`.

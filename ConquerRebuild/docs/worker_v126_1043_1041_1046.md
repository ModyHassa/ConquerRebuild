# v126 — 1043 (verified structure), 1046 (action word), 1041 (channel), and what is still open

All VAs in `MsgServer.exe` (imagebase 0x140000000). Everything below was re-read from the binary in
this wave; anything not proven is marked UNKNOWN.

## 1043 — the case body is a TAIL CALL
`case 0x25`, body 0x140135433 is only `call 0x140162620` + `jmp` to the router epilogue, so the
worker-era description "the body iterates" really belongs to **0x140162620**.

Structure of 0x140162620, all verified:
1. `cmpq $0,0x1110(%rcx)` (0x14016265d) - the `CUser+0x1110` container must be non-NULL, else the
   CHECKF at 0x14016268b logs and it returns.
2. Iteration: `container->vt[0x10]()` = begin (0x140162698), compare with `r12`
   (`cmp %rax,%r12` 0x1401626ac), `container->vt[0x18](key)` = the element (0x1401626da); a NULL
   element skips (0x1401626e3).
3. Per element, exact order:
   * `ebx = elem->OldLevel()`  (accessor 0x14039d8e0 = `mov 0x19(%rcx),%al`)
   * `al = elem->Level()`      (accessor 0x14039d7e0 = `mov 0x18(%rcx),%al`)
   * `cmp al,bl ; jae skip` → **only when level < old_level** it calls
     `0x14039d960(elem, level, 0)` = `SetOldLevel` (first store inside is `mov %dl,0x19(%rcx)`).
   * unconditionally `0x14039d8f0(elem, 1)` (the second setter - byte field, the "unlearn" flag).
   * `ebp = elem->NType()` (0x14039d760 = `mov 0x10(%rcx),%eax`).
   * `key = 0x14039d9d0(elem)` = `elem id` (`mov 0x8(%rcx),%eax`).
4. `container->vt[0x28](key)` = the erase (0x14016274a).
5. Packet: `0x140362560` ctor + `0x140362620(msg, userID, ...)` with **`mov $0x6e,%eax`**
   (0x140162796) = **action id 110**, then `user->vt[0x350]` = send to that client only
   (0x1401627f2).
UNKNOWN: which of the two helper slots (`+0x08`/`+0x10` of the message body) receives `ebp`
(the element nType) and which receives the 0 - the argument setup at 0x140162788..0x1627ab mixes
stack slots `[rsp+0x20]`(word), `[rsp+0x28]`(0x6e), `[rsp+0x30]`(ebp), `[rsp+0x38]`(0) and the
`0x140362620` parameter-to-offset map is only partially proven. **Do not port the packet until that
mapping is nailed**; the state part (old_level / unlearn / erase order above) is fully verified.

**`data` column**, same cell-4 idiom as 1096), the position/dir getters (`+0x50`, `+0x48`, `+0x40`,
`+0x08`), then `mov $0x7e,%eax` (0x140135601) = **action id 126** into `0x140362620`.
The failing path logs line `0x2963` with the literal `msg.Create(pUser->GetID(), pUser->GetPosX(),
pUser->GetPosY(), pUser->GetDir(), actionOpenDialog...`.
UNKNOWN: the recipient slot (self vs broadcast) is not read yet, and which message field takes the
`data` value.
